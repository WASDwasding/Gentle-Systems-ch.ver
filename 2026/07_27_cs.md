# 27_cs | 查询优化器中的“等价而择优”

## 1. 这篇短文对应的计算机科学概念

这篇 ”人心中的优化器：等价而择优“，对应的是数据库系统中的一个核心思想：**查询优化器只能改变执行路径，不能改变查询结果**。

更严格地说，优化器在改写 SQL 时，必须满足**语义等价**。也就是说，改写前后虽然写法不同、执行顺序不同、访问路径不同，但最终返回给用户的结果必须一致。

这件事在数据库内核里非常重要，因为优化的目标从来不是“写出另一条 SQL”，而是“在不改变原意的前提下，更快、更省资源地完成同样的任务”。

## 2. 什么是查询优化器

查询优化器是数据库中的一个模块。用户提交 SQL 之后，数据库不会立刻机械地照着字面顺序执行，而是会先分析这条查询，寻找更好的执行方式。

优化器通常会做两类事情：

1. **等价改写**
   把一种表达形式，改写成另一种结果相同但更适合执行的形式。

2. **执行计划选择**
   在多个可行方案里，选出代价更低的一条路径，比如选择索引扫描还是全表扫描，选择哪张表先连接，选择哪种 Join 算法。

所以，优化器的本质不是“改答案”，而是“改路线”。

## 3. 什么叫“等价”

“等价”是优化器最重要的边界。

如果原始 SQL 的含义是“找出满足条件的记录”，那么无论优化器怎么重排、怎么下推谓词、怎么选择索引，它都必须返回同一批记录。否则这就不是优化，而是篡改。

在数据库里，常见的等价变换包括：

- **谓词下推**
  尽早应用过滤条件，减少后续处理的数据量。

- **投影下推**
  尽早去掉不需要的列，减少中间结果宽度。

- **连接顺序调整**
  在多表连接中改变 Join 顺序，但保持最终结果不变。

- **子查询改写**
  把某些子查询改写为 Join、半连接或其他更易执行的形式。

这些改写能成立，前提都是：**结果等价**。

## 4. 什么叫“择优”

“择优”就是在满足等价的前提下，选择更好的执行策略。

“更好”通常体现在这些维度上：

- 扫描更少的数据页
- 使用更合适的索引
- 产生更小的中间结果
- 减少 CPU 计算量
- 减少磁盘 I/O
- 减少内存占用

所以，“择优”不是抽象的审美判断，而是工程上的成本控制。

数据库里经常会说：

- **Rule-Based Optimization, RBO**
  基于规则做改写，例如“先过滤，再连接”。

- **Cost-Based Optimization, CBO**
  基于代价估算选择方案，例如估算行数、选择率、I/O 成本，再决定哪条计划更优。

RBO 解决“能不能这样改”，CBO 解决“改完后哪条更值”。

## 5. 为什么这和短文能对应上

这篇短文最妙的地方，是它没有停留在“借用了一个技术名词”，而是真的和优化器的约束逻辑对应上了。

短文里有三层映射关系：

### 5.1 原始输入，对应原始 SQL

外界的评价、建议、批评，往往混杂着情绪、语气、偏见和表达习惯。

这就像用户写出来的一条原始 SQL。它的目标可能是合理的，但写法未必最适合直接执行。

### 5.2 保留事实，对应结果等价

短文里说：

> 不会因为对方语气尖锐，就否定事实；也不会因为对方态度不好，就全盘拒绝成长。

这对应的正是“结果不能变”。

也就是说，真正有价值的部分，比如问题本身、客观不足、可执行建议，必须被保留下来。不能因为输入形式不好，就把有用信息一起丢掉。

### 5.3 过滤情绪，对应执行优化

短文里说：

> 把伤人的句式，改写成平和的提醒；把尖锐的指责，转换成具体的待办。

这正像优化器所做的事情：

- 不执着于原始写法
- 只保留有意义的语义
- 换一种更适合处理的形式

这不是逃避问题，而是以更低的心理成本处理同样的问题。

## 6. 一个最小 SQL 例子

下面给一个很简单的例子。

原始查询：

```sql
SELECT name
FROM student
WHERE age > 18 AND major = 'CS';
```

如果 `major` 上有索引，数据库可能会优先利用 `major = 'CS'` 做过滤，再继续判断 `age > 18`。从用户角度看，SQL 还是那条 SQL，但数据库内部可能已经选择了一个更省成本的执行方式。

再看一个更能体现“先过滤再连接”的例子：

```sql
SELECT s.name, c.course_name
FROM student s
JOIN choose_record r ON s.id = r.student_id
JOIN course c ON r.course_id = c.id
WHERE s.grade = '2024';
```

优化器可能会先把 `student` 表中过滤出 `grade = '2024'` 的学生，再去做后续连接。这样可以明显减少 Join 时参与计算的数据量。

注意，这里的关键不是“写法变了”，而是：

- 查询目标没变
- 最终结果没变
- 执行成本下降了

这就是“等价而择优”。

## 7. 这篇短文背后的数据库内核训练

如果把这篇短文当成一次真正的学习入口，那么你今天至少可以顺着它学下面几个知识点：

- 查询处理流程：`SQL -> 解析 -> 逻辑计划 -> 优化 -> 物理计划 -> 执行`
- 逻辑优化与物理优化的区别
- 关系代数中的等价规则
- 谓词下推为什么能减少中间结果
- 优化器为什么需要统计信息
- 为什么错误的基数估算会导致错误的最优计划

这几个点一旦学清楚，你对数据库内核的理解就会往前走一大步，因为你会开始从“数据库会执行 SQL”进化到“数据库为什么这样执行 SQL”。

## 8. 这篇内容真正值得记住的一句话

在数据库里，优化器的成熟，不是因为它敢随便改写，而是因为它**只在等价约束之内追求最优**。

在人身上也是一样。

真正成熟的心智，不是被外界原样击中，也不是拒绝一切输入，而是能在保留事实的前提下，重构接收方式，降低内耗，提高成长效率。

所以这篇短文和数据库优化器之间，最准确的对应关系可以概括成一句话：

> 等价，是边界；择优，是能力。
